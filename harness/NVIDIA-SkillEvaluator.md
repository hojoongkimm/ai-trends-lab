## 1. 연구 배경 및 시스템 병목 (Systems Research Problem)

에이전트 스킬은 문서와 스크립트의 묶음이고, 지금까지의 품질 관리는 그 **문서를 읽는** 방식이었다. 구조 검사, LLM 판정, 린트, 보안 스캔은 모두 같은 성질을 공유한다. 스킬을 실행하지 않는다. 이 저장소가 지적하는 병목은 그 공백이다.

1. **관찰 불가능한 실패 모드(Unobservable Failure Modes)**: 스킬이 깨끗하게 스캔을 통과하고도 실패한다. (a) 관련 질문에서 에이전트가 스킬을 발견하지 못함, (b) 문서는 읽었으나 다른 스크립트를 잘못된 인자로 호출, (c) 결과는 맞으나 보고를 잘못함, (d) 같은 워크스페이스의 다른 스킬과 충돌, (e) 모델 업데이트로 문서 해석이 달라져 조용히 회귀. 다섯 중 어느 것도 문서만으로는 보이지 않는다.
2. **스캔 지표 사이의 불일치(Inter-Scan Disagreement)**: 정적 점수와 LLM 판정 점수는 같은 스킬 집합에서 거의 상관하지 않는다. 실측 Spearman $\rho = 0.14$, Pearson $r = 0.08$이다. 두 방법이 각각 94.5%와 86.2%를 통과시키는데도 서로 동의하지 않는다면, 둘은 같은 잣대가 아니다.
3. **능력 패키지의 조건부 가치(Conditional Value)**: 스킬의 가치는 단독 성질이 아니라 (모델, 하네스, 과업, 샌드박스, 채점 정책)의 함수다. 절대 점수는 "이 스킬이 좋다"와 "이 모델이 이 과업에 강하다"와 "이 판정자가 관대하다"를 뒤섞는다.
4. **레지스트리 규모의 비용(Cost at Registry Scale)**: 스킬 수 $N$, 하네스 $K$, 사례 $C$, 시도 $A$에 대해 쌍 조건 평가는 최대 $2NKCA$ 컨테이너 실행을 요구한다. 비용을 설계 변수로 다루지 않으면 평가는 표본 조사로 퇴화한다.

응답은 세 층의 분리다. 값싼 검증이 게이트를 잡고, 중간층이 중복을 걸러내며, 비싼 계층이 짝지은 실측으로 한계 기여를 잰다. 이 중 세 번째가 이 저장소의 실질적 기여다.

## 2. 아키텍처 및 수학적 정식화 (Architecture & Formulation)

### A. 비용 순서로 정렬된 세 계층

| 계층 | 질문 | LLM 호출 | 실패 시 의미 |
| :--- | :--- | :--- | :--- |
| Tier 1 검증 | 안전하고 형식이 맞고 하네스가 로드하는가 | 없음(LLM 검사는 선택) | 게이트 |
| Tier 2 중복 | 지침이 반복되거나 다른 스킬과 겹치는가 | 임베딩 + 채팅 | 기본 게이트(`--no-block-on-dedup`로 해제) |
| Tier 3 실측 | 이 스킬이 에이전트를 실제로 돕는가 | 있음 | `--block-on-agent-eval`일 때만 게이트 |

설계 원칙은 "검사는 값싼 것부터"이다. Tier 1은 API 키 없이 밀리초 단위로 돌고, Tier 3은 프로바이더·에이전트·샌드박스를 모두 요구한다. 계층이 독립 호출 가능하다는 점이 중요하다. 저장소 전체 파이프라인을 신뢰하지 않아도 한 계층만 CI에 붙일 수 있다.

특히 `harness-check`는 LLM 호출 없이 "이 스킬이 로드되는가"만 답한다. README의 예시는 여섯 하네스 중 두 개가 실패하는 상황을 보여준다. Codex는 설명을 1,021자에서 잘라 붙이고, `copilot-cli`는 설명이 1,028 UTF-16 단위로 1,024 한도를 4 넘겨 로드되지 않으며, `claude-code`는 `.agents/skills` 디렉터리를 스캔하지 않는다. 스킬 품질 이전에 **전달 형식**이 실패하는 층이 따로 있다는 관찰이다.

### B. 정적 점수의 가산 구조

네 차원 $d \in \lbrace \text{Correctness}, \text{Discoverability}, \text{Reliability}, \text{Efficiency} \rbrace$는 가중치 $\lbrace 0.35, 0.25, 0.25, 0.15 \rbrace$를 갖고, 각 차원은 100에서 규칙 위반마다 심각도 가중 감점을 뺀다. 규칙 $r$의 위반 여부 $v_r \in \lbrace 0,1 \rbrace$와 심각도 $s_r$에 대해

$$
S_{\text{struct}} = \sum_{d} w_d \max\left(0,\ 100 - \sum_{r \in R_d} s_r v_r\right)
$$

규칙은 약 50개, 기본 게이트는 70점이다. 145개 실제 스킬에서 평균 79.2, 중앙값 79.8, 표준편차 4.9였고, 94.5%가 70점을 넘었으나 80점을 넘은 것은 48.9%뿐이다. 분포가 게이트 바로 위에 몰려 있다는 뜻이고, 이는 게이트가 변별력이 아니라 **저자 피드백 도구**로 기능한다는 신호다.

위반 프로파일은 더 노골적이다. 상위 10개 위반 규칙 중 네 개가 프런트매터 계약이고, `tools` 미선언 99.3%, `Limitations` 절 없음 97.9%, `author` 없음 97.2%, `tags` 없음 91.7%다. 스펙이 요구하는 필드를 91–99%의 스킬이 빠뜨렸는데 게이트가 통과시킨다. **선언된 계약은 강제되지 않는 희망사항**이라는 뜻이며, 이 저장소는 그래서 엄격 모드 게이팅을 선택 옵션으로 제공한다.

### C. LLM 판정의 조건부 성질

판정 루브릭은 9개 기본 기준(설명 명료성, 지시 명료성, 예시 품질, 문서 완결성, 범위 정의, 전문적 어조, 트리거 시뮬레이션, 워크플로 완결성, 오류 처리 품질)에 보조 자료가 있을 때 1개(구조 일관성)가 붙는다. 온도는 0으로 고정된다. 판정자 교체 실험에서 가장 엄격한 판정자와 가장 관대한 판정자의 차이는 0–10 척도에서 약 1.5점이었고, 코퍼스 내 상대 순위는 대체로 보존됐다. 즉 **절대값은 판정자에 종속되고 순위는 대체로 전이된다**는, 흔하지만 명시되기 드문 성질을 측정해 문서화했다.

### D. Skill Lift: 짝지은 차분

과업·에이전트·모델·평가 자산·채점 정책을 고정하고 대상 스킬의 유무만 바꾼 두 조건 $\text{with}, \text{base}$에 대해, 지표 집합 $M$의 평균 차이로 정의한다.

$$
\mathrm{Lift}_{s,a} = \frac{1}{\lvert M \rvert} \sum_{m \in M} \left( \overline{S}^{\mathrm{with}}_{s,a,m} - \overline{S}^{\mathrm{base}}_{s,a,m} \right)
$$

기본 $M$은 6개 지표(security, skill_execution, skill_efficiency, accuracy, goal_accuracy, behavior_check)이고 각 $1/6$ 등가중이다. 결과만 보는 변형은 accuracy와 goal_accuracy의 평균이다. 차분 설계의 효용은 직관적으로 명확하다. 절대 점수는 $\text{skill} + \text{model} + \text{judge}$ 성분의 합이고, 세 성분을 고정한 차분은 스킬 성분만 남긴다.

### E. 기준선 설계: 참조 미끼와 라우팅 프리미엄

순진한 기준선은 작업 공간에서 대상 스킬만 지우는 것이다. 그러면 두 성분이 뒤섞인다. 스킬의 **내용**(무엇을 하라고 말하는가)과 스킬의 **발견 가능성**(찾을 스킬이 존재한다는 사실). 그래서 기준선에도 API 디버거, 로그 분류기, 설정 검증기, 릴리스 계획기 같은 참조 미끼를 고정 배치한다. 에이전트는 두 조건 모두에서 선택을 수행해야 하고, 차분은 대상 스킬의 한계 기여만 남긴다.

두 모드로 성분을 더 분해한다. 격리 모드(작업 공간에 대상 스킬만)의 리프트는 내용 기여이고, 그룹 모드(대상 + 고정 지원 스킬)의 리프트는 내용 + 라우팅 기여다.

$$
\mathrm{Lift}_{\text{iso}} : \text{content only}, \qquad \mathrm{Lift}_{\text{grp}} : \text{content and routing}
$$

둘의 차이는 라우팅 프리미엄이다.

$$
\Pi_{\text{route}} = \mathrm{Lift}_{grp} - \mathrm{Lift}_{iso}
$$

$\Pi_{\text{route}} \approx 0$이거나 음수면 이름과 설명이 이웃 스킬과 구별되지 않는다는 뜻이고, 내용 품질이 높아도 저자가 고칠 지점이 명확해진다. 이 분해는 "스킬이 안 먹힌다"는 현상을 두 개의 서로 다른 처방(문서 내용 vs 설명·트리거 문구)으로 나누는 진단 도구다.

### F. 궤적 계약: ATIF

평가기가 유용하려면 에이전트가 같은 형식으로 궤적을 내놓아야 한다. ATIF(Agent Trajectory Interchange Format)는 단계의 순서 목록이고, 각 단계는 출처, 메시지, 도구 호출(함수명 + 인자), 관찰을 담는다. 구조적 도구 호출 API를 가진 하네스(Claude Code, Codex)는 이를 기본 출력하고, 평문 로그만 내는 하네스(cursor-cli 등)는 휴리스틱 어댑터가 합성 궤적으로 변환한다. 이 정규화가 없으면 하네스 수 $K$마다 평가기를 다시 써야 한다. 있는 경우 평가기는 하나이고 $K$는 교체 가능한 축이 된다.

### G. 확장 비용과 결과

쌍 조건 평가의 상한은 $2NKCA$ 컨테이너 실행이다. 다중 시도는 pass@k 보고를 가능하게 하고, 통과 후 중단을 켜면 남은 시도를 건너뛴다. 실측 규모는 다음과 같다.

| 항목 | 값 |
| :--- | :--- |
| 스캔한 스킬 | 145 |
| 실측 변형 | 89 (확장 연구 25개 제외) |
| 주 분석 생산 스킬 | 64 중 58개가 채점된 쌍 사례 보유 |
| 주 하네스 | 4 |
| 채점된 쌍 과업 사례 | 947 |
| 조건 실행 / 보상 행 | 578 / 2,077 |
| 저장된 ATIF 궤적 / 도구 호출 / 행동 관찰 | 2,022 / 11,642 / 9,091 |
| 평균 복합 리프트 (95% CI) | 0.2134 [0.1967, 0.2301] |
| 결과만 리프트 | 0.1799 |
| 스킬 있음 / 기준선 절대 평균 | 0.7460 / 0.5326 |
| 양(+) 리프트 사례 | 689 양, 171 영, 87 음 (중앙값 0.1717) |

지표별 분해가 핵심이다. 최종 정답 개선(accuracy +0.1431)보다 궤적 수준 신호의 개선이 크다. skill_execution +0.3263, behavior_check +0.2983, skill_efficiency +0.2758이다. 즉 스킬의 주된 효과는 "답을 더 잘 맞힌다"보다 "예상한 절차를 밟는다"에 있다. skill_efficiency는 평균 리프트가 세 번째로 크지만 양(+) 사례 비율이 41.7%에 그친다. 효율은 정확성이나 절차 완결성과 교환되며 분산이 큰 지표라는 뜻이고, 단일 평균으로 보고하면 오해를 만든다.

하네스별 평균은 OpenCode 0.3611, Claude Code 0.2904, Codex 0.1264, Terminus-2 0.0896이다. 표본이 균형이 아니므로(각 56, 50, 34, 37 셀) 순위표로 읽으면 안 된다고 스스로 밝힌다. 같은 Codex 하네스에서 모델만 바꾼 슬라이스에서는 기준선이 크게 오르면서 **리프트가 줄어든다**. 스킬의 한계 가치는 모델이 강해질수록 감소할 수 있고, 이것이 모델 업데이트 후 재평가를 정기화해야 하는 이유다.

라우팅 스트레스 시험은 별도다. 보이는 스킬 수를 1에서 50까지 늘리면 1–20 구간에서는 리프트가 0.133–0.149로 유지되지만 평균 소요가 258초에서 451초로 늘고, 50개에서는 통과율이 0.55로 떨어지고 소요가 1,290초가 된다. 발견 가능성의 비용이 선형이 아니라 임계점 이후 급증한다는 관찰이다.

## 4. 한계점 및 실패 모드 (Limitations & Trade-offs)

1. **정적 점수와 실측 리프트의 무상관**: 생산 스킬 62개의 Tier 1 구조 점수와 실측 리프트의 Spearman은 $-0.0181$(95% CI $[-0.2667, 0.2327]$), Tier 2 LLM 판정은 $-0.0266$이다. 0과 구별되지 않는다. 이는 스캔이 무의미하다는 뜻이 아니라, 스캔 점수를 런타임 품질의 대리 지표로 쓰면 안 된다는 뜻이다. 실무적으로는 CI에서 정적 점수를 품질 근거로 인용하는 관행을 금지해야 한다는 결론이 나온다.
2. **판정자 보정의 부재**: 문서 루브릭은 세 판정자 회전으로 민감도를 쟀지만, 실측 궤적 채점의 판정자 간 일치도와 사람 보정은 측정되지 않았다고 명시한다. 리프트 수치의 신뢰 구간은 표본 변동만 반영하고 판정자 변동은 반영하지 않는다.
3. **군집 구조** : 947개 사례를 독립 표본처럼 다루면 안 된다. 스킬·하네스·시도로 군집되어 있고, 저자들은 스킬 부트스트랩 [0.1898, 0.2350], 스킬-에이전트 셀 부트스트랩 [0.1880, 0.2385]를 함께 보고한다. 세 구간이 모두 양수라는 점이 결론을 지탱하지만, 사례 단위 신뢰구간만 인용하면 과신이 된다.
4. **반복 실행의 부족**: 201개 셀 중 두 번의 쌍 시도를 가진 것은 88개다. 반복 셀의 리프트 표준편차 중앙값은 0.0319, 평균 0.0699로 작지 않다. 단일 시도 셀은 효과 크기 보고에만 쓰고 셀 분산 주장에는 쓰지 않는다고 밝힌다.
5. **음의 리프트의 해석 모호**: 87개 사례가 음수이고, 그중 일부는 실행 불안정(스킬 조건 실행이 채점 불가로 끝남)이다. 저자들도 "발견되지 않음"과 "발견했지만 오용"을 궤적으로 분리해 읽어야 한다고 말한다. 집계 수치만 보면 두 원인이 같은 음수로 보인다.
6. **정보 누출 위험**: 쌍 과업은 대표 스킬 ID를 익명화하고 원시 궤적을 공개하지 않는다(내부 호스트명·경로·제품 식별자 포함). 재현성은 방법론 수준에서만 성립한다.
7. **코퍼스 편중**: System Access 49, Deployment 41, Platform 29, Data Infra 21로 대부분을 차지하고 Troubleshooting 3, Dev-Tooling 1, Other 1이다. 같은 리프트 분포가 창작·디버깅 계열에 성립한다고 주장하지 않는다.
8. **기업 내부 엔드포인트**: VPN 뒤 엔드포인트를 쓰는 스킬은 컨테이너에서 네트워크 오류를 받아 goal_accuracy 절대값이 하한이 된다. 차분은 같은 조건이라 유효하지만 절대 성공률 비교는 왜곡된다.
9. **보안 지표의 분리 필요성**: 보안을 behavior_check와 별도 지표로 둔 이유가 사례에서 드러난다. 정적 검토가 11/11 검사·89점을 보고한 공개 스킬이, 중간 산출물에 합성 `nvapi-` 카나리를 남긴 채 최종 파일만 고쳤다. 최종 답만 보면 통과, 산출물을 보면 유출이다.
10. **SDK·프로바이더 종속**: 실측에는 프로바이더 키, 지원 에이전트, 실행 중인 샌드박스가 필요하다. "키 없이 검증"이라는 진입 경로는 Tier 1에만 해당하고, Tier 3는 비용과 접근 권한의 문턱이 있다.

## 5. 연구 및 실무 활용 포인트 (Research Impact)

- **차분 설계의 일반성**: "이 도구가 도움이 되는가"라는 질문은 어디서나 교란된다. 지원 스킬을 고정한 쌍 조건, 참조 미끼가 있는 기준선, 격리/그룹 두 모드는 프롬프트·툴·RAG·모델 업그레이드 평가에 그대로 옮길 수 있는 실험 설계 템플릿이다.
- **발견과 사용의 분해**: 라우팅 프리미엄 $\Pi_{\text{route}}$는 스킬 생태계의 실패를 두 처방으로 나눈다. 이름·설명 개선과 본문 개선은 다른 작업이고 비용도 다르다. 이 분해가 없는 평가는 두 문제를 하나의 점수로 뭉갠다.
- **궤적 계약의 가치**: ATIF 같은 정규화 계층이 있으면 평가기 수가 하네스 수에 곱해지지 않는다. 반대로 평문 로그만 내는 하네스는 휴리스틱 변환에서 정보를 잃는다. 하네스 설계자에게 "구조화 궤적을 내라"는 요구는 평가 생태계 참여의 전제 조건이 된다.
- **정적 지표의 올바른 용도**: $\rho \approx 0$은 스캔 폐기가 아니라 용도 제한이다. 스캔은 저자 피드백과 형식 회귀 방지에 쓰고, 품질 근거로는 쓰지 않는다. 이 구분을 문서에 적는 것만으로 리뷰 문화가 달라진다.
- **모델-스킬 상호작용**: 기준선이 강해지면 리프트가 줄어든다. 스킬 자산의 가치는 모델 세대에 종속되므로, 모델 업데이트를 트리거로 한 정기 재평가가 필요하다. 이는 "스킬을 한 번 잘 쓰면 계속 좋다"는 가정을 반증한다.
- **후속 연구 방향**: (i) 실측 궤적 채점의 사람 보정과 판정자 분산 전파, (ii) 라우팅 프리미엄과 스킬 설명 길이·어휘의 인과 관계, (iii) 리프트 음수 사례의 자동 분류기, (iv) 스킬 수 증가에 따른 발견 실패의 임계점 모델링, (v) 플러그인·번들 단위 개입 효과의 분해.
